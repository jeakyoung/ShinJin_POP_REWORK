# 창고 설정과 우선순위

로그인 화면의 톱니바퀴 설정에서 단말을 선택하고 창고 설정을 연다. 사업장을 먼저 설정한 뒤 창고 전용 암호를 확인하면 사원 로그인 없이 현재 단말·사업장·작업장의 창고 역할과 우선순위를 저장할 수 있다. 적용한 값은 해당 브라우저 프로필의 단말 로컬 파일에 저장되고, 로그인 성공 시 업무 세션에 적용된다.

| 원본 경로 | 웹 동작 |
|---|---|
| POPSYS/frmSetting.cs 672–735 | 공장 설정 선행 → frmPassWord → frmLocation → frmLocationIdx. 앞 창이 OK를 반환할 때만 다음 창을 열고, 우선순위 저장 성공 후 설정 타일을 갱신한다. |
| frmPassWord.cs 59–109, 123–166, 190–243, Designer 108–168 | 암호에 포커스, 가림 입력, 확인 또는 비어 있지 않은 입력의 Enter, X·닫기로 취소. 오입력 시 원문 메시지 뒤 입력을 비우고 포커스를 돌린다. 터치 키보드는 브라우저의 암호 입력 컨트롤을 사용한다. |
| frmLocation.cs 72–223, 358–389, 432–486, 499–601, 641–700 | 순번·사업장·창고코드·창고명과 투입/반납/양품/불량/투입보조를 표시한다. 한 창고에 여러 역할을 줄 수 있다. 역할 머리글은 그 열만 전체 선택/해제한다. ‘창고 정보를 저장 하시겠습니까?’에 ‘예’를 선택하면 각 역할의 행을 목록 순서로 저장한다. 빈 역할을 허용한다. |
| frmLocationIdx.cs 122–301, 303–413, 416–600 | 첫 저장 결과를 독립된 다섯 표에 읽어 들인다. 위/아래는 포커스한 행을 같은 표에서 한 칸 이동시킨다. 처음/끝에서 범위 밖 이동은 무변경이며 순번은 1부터 다시 매긴다. 저장은 별도 확인 없이 다섯 순서를 한 번에 반영한다. 취소하면 첫 저장은 유지한다. |
| frmPlant.cs 462–511, frmProcess.cs 804–839 | 공장 설정 저장은 창고 사본을 지운다. 공정 설정 저장은 창고 사본을 보존한다. |

frmLocation과 frmLocationIdx는 서로 다른 저장 경계다. 기존 단일 창고 코드로 다섯 역할을 추론하지 않는다. 새 역할 사본의 적용 시점은 다음 로그인이다. 설정 새로고침은 로그인에 고정한 역할 사본을 교체하지 않는다. 기존 생산 데모의 단일 LOT 창고 매핑은 별개의 소비 계약이며 이 패치에서 현장 코드에 대응시키지 않는다.

## HTTP 계약

로그인 전 설정의 기본 경로는 `/api/pop/prelogin-details/{terminalId}/warehouse`이다. 서버는 브라우저·단말·사업장·작업장, 창고 암호 인증, 화면 단계와 설정 버전을 검사한다. 이전 인증된 호출자의 호환 경로는 `/api/pop/admin/terminal-settings/{terminalId}/warehouse`이다.

| 호출 | 계약 |
|---|---|
| POST /entry | 요청의 password를 설정 암호 어댑터가 비교한다. 응답은 해당 범위 후보, 저장/로그인 적용 역할 목록, 버전, 조회/편집 권한과 이번 진입 식별자를 담는다. 다시 들어가면 새 식별자를 발급한다. |
| PUT /selection | entry, expectedVersion, roles. 역할 키는 issue, returns, good, bad, auxiliary다. 등록된 창고 코드 목록을 각 역할에 보낸다. 서버는 중복·누락·다른 범위 코드를 검사하고 후보 표의 순서로 정렬한다. 성공 응답은 priority 단계다. |
| PUT /priority | 동일한 입력 구조다. 각 역할의 멤버가 첫 저장과 같아야 하고 배열 순서가 우선순위다. 성공 시 진입을 닫는다. |
| POST /close | entry를 보내면 해당 세션의 그 진입을 닫는다. 선택이나 순서 초안을 쓰지 않는다. |

인증된 호환 경로는 비로그인 요청에 401을 반환한다. 창고 암호 오입력·다른 세션/단말은 403, 버전/단계 충돌은 409, 잘못된 목록은 422, 설정 암호를 확인할 수 없으면 503이다. 예전 전체 설정 PUT으로 단일 창고를 바꾸거나 /section/warehouse로 직접 쓰는 요청도 거절한다.

## 설정 경로 시험

시험은 `tools/equipment-settings/verify.py`의 warehouse, missing, official suite로 실행한다. 각 suite는 서로 분리된 루프백 Spring과 Chrome을 사용한다. warehouse는 demo와 warehouse-test 프로필에서 시험 프로세스 전용 값을 생성한다. 주입 경로는 서버 환경 변수 `POP_WAREHOUSE_TEST_PASSWORD`, 합성 후보 목록은 `POP_WAREHOUSE_TEST_CATALOG`이다. missing은 값을 주입하지 않고 official은 demo 프로필만 사용한다. 저장소·기본 설정·인쇄 인증에 암호값을 두지 않는다. 캡처는 빈 입력창과 인증 후 업무 상태에서만 한다.

분리된 시험 카탈로그는 warehouse-catalog.tsv에 있다. 같은 사업장·작업장의 두 단말은 같은 후보를 읽지만 설정 사본은 각각 소유한다. 다른 공장에서는 같은 코드라도 별도 후보를 조회한다. P1/005의 합성 창고 가·나·다로 확인한 최종 순서는 다음과 같다.

| 역할 | Chrome에서 저장한 순서 | 재로그인 후 대조 대상 |
|---|---|---|
| 투입 | 나, 가, 다 | issue |
| 반납 | 다, 가, 나 | returns |
| 양품 | 나, 다, 가 | good |
| 불량 | 가, 다, 나 | bad |
| 투입보조 | 나 | auxiliary |

원본 SP_POP_PASSWORD는 인수 없이 첫 결과의 CTRL_ITEM을 대소문자 구분 그대로 비교한다. 첫 행이 없으면 원본은 OK를 반환하지 않는다. SP_POP_SYS_WAREHOUSE_01_LIST에는 factory_code, plant_code, workcenter_code, division=SELECT를 전달하며 결과 행의 코드/이름과 다섯 체크 필드를 사용한다. 원본 INI의 두 창고 설정 파일은 저장 전에 삭제되고 역할별 코드/이름이 순번대로 기록된다. SP 내부 정의와 현장 데이터는 이 시험의 입력이 아니다. DB 연결이나 SQL 실행 없이 이 경로를 검증했다.
