# 로그인 전 환경설정과 메인 복귀

로그인 톱니 → 환경설정 → 정보 확인 → 확인 또는 X → 환경설정 → 닫기 → 로그인 순서로 돌아온다. 스캔 창은 사원번호 입력과 닫기 버튼으로 구성된다. 입력 또는 붙여넣기 뒤 Enter로 로그인한다. 사용자 승인에 따라 기존 demo 스캔 코드 0000을 사용할 수 있다. 일반 화면에서 사번·암호·스캔코드 힌트나 단말·장치 후보를 표시하지 않는다.

## 웹의 권한과 공개 데이터

로그인 전의 기존 Spring 쓰기 권한은 유지한다. 현재 운영 웹의 로그인 전 편집 허용 범위는 사용자 결정 대기다. 이번 패치는 편집 타일의 원본 선행 조건을 먼저 확인하고 조건이 충족되면 로그인 후 단말 설정으로 안내한다. 익명 사용자에게 단말 관리자 세션, 창고 설정 암호 통과 권한 또는 장치 선택권을 부여하지 않는다.

`GET /api/pop/prelogin-settings`는 서버가 선택한 단말 ID, 그룹 대상 여부, 합성 누락 항목, 로그인 가능 여부, 허용된 버전 문자열 및 FTP·DB 주소값의 존재 여부만 보낸다. 익명 화면은 작업자·장치 카탈로그를 요청하지 않는다. 기존 demo는 이전 첫 단말 선택을 이어받으며 사용자가 확정한 구성 완료 상태로 시작한다. 선택된 작업장의 그룹 여부는 서버의 저장 작업장 또는 기존 데이터셋에서 판정한다.

원본 정보창의 행과 배치는 유지한다. 구성된 주소·경로·DB명 칸은 ‘표시 제한’으로 표시한다. 주소·포트·DB명·자격증명·파일 경로를 전송하지 않는다. 버전은 별도 시험값만 허용하고 기본 demo에 확인되지 않은 설치 버전을 넣지 않는다.

## 합성 검증

`demo,prelogin-test`에서만 `shinjin.prelogin.terminal`, `shinjin.prelogin.missing`, `shinjin.prelogin.version`을 읽는다. 단말은 기존 데이터셋에서 고르고, missing은 허용된 파일 종류만 받는다. 이 프로필은 브라우저에서 다른 단말 ID를 보내도 우회하지 못하도록 Spring 로그인 시 다시 검사한다. 필수 설정 누락 시 수동·스캔 모두 409이며 새 인증 세션을 만들지 않는다. 기본 demo의 기존 단말별 로그인 API 계약은 유지한다.

브라우저 검증은 `tools/prelogin/verify.py`에 Java 17, JDBC 없는 클래스패스, 증거 디렉터리와 suite를 지정한다. default/missing/single 및 005/105 그룹 경로, ordinary와 omission을 제공한다. 단일 누락은 omission --omit 뒤에 파일 종류를 지정한다. 15177 비교는 verify-browser.mjs의 before 모드로 기록했다. 운영 설정·DB·SQL·FTP·실장치·업데이터를 실행하지 않는다.

## Load 이후 파일 유무와 주소 유무

frmSetting.cs 272–289는 FTP·DB 파일의 존재로 정보 타일을 칠한다. frmInformation.cs 65–121은 파일에서 읽은 각 IP 값으로 해당 정보행을 칠한다. 파일이 있고 FTP 주소만 비어 있으면 정보 타일은 구성 완료 색이며 FTP와 버전만 빨간 NONE이다. DB 주소만 비면 DB 두 행만 빨간 NONE이다. 로그인 설정 검사는 파일 존재를 사용한다. 정보창을 닫으면 frmSetting.cs 749–775처럼 현재 단말 상태를 다시 읽는다.

시험 프로필에서만 `shinjin.prelogin.empty-address`에 `ftp`, `db` 또는 둘 다를 쉼표로 지정할 수 있다. 응답의 `ftpAddressPresent`와 `dbAddressPresent`는 불리언이다. 주소값이 없는 FTP의 버전 필드는 빈 문자열이고 정보창은 원본대로 NONE을 표시한다. 기존 HTTP 하네스의 `--suite empty-ftp`와 `--suite empty-db`가 이 계약을 검사한다.

frmPlant.cs 446–515에서 저장 확인 후 공정·설비·POP ID·그룹·재질·창고 파일을 삭제하고 사업장을 다시 쓴다. 프린터와 고정 창고 파일은 보존한다. 기본 demo는 구성된 단말이라는 사용자 결정을 따른다. 로그인 차단은 별도 미설정 시험에 한정한다. 로그인 전 쓰기 권한은 기존 서버 계약을 따른다.
