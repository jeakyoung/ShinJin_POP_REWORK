# 공장이송 합성 데이터셋

`transfer.json`은 출고·입고 폼과 출고요청 리스트 미리보기용 로컬 데이터다. 사업장 이름, 단말 배정, 창고와 ERP 코드의 대응, 보고서 규격과 비고는 예시다. 숫자 상수 `132`와 `000001`은 원본 조회 조건에 쓰인다.

데모 프로필에서 `--shinjin.demo.transfer-master=<transfer.json의 절대경로>`로 선택한다. 작업이력의 `shinjin.demo.dataset`과 독립이다. 설정하지 않으면 기존 데모 경로가 열린다. 명시한 파일을 읽을 수 없으면 기동에 실패한다. 빈 테이블을 명시하면 상세 폼에 조회 결과가 없다.

| 항목 | 사용처 |
| --- | --- |
| `terminalPlants` | 인증 단말의 샘플 사업장을 지정한다. 원본의 단말 설정값 `ComLogin.clsPlantInfo.sPlant_Code`에 해당한다. |
| `TCO101` | `CODE_ID1=132`인 행을 코드순으로 표시한다. 선택 키는 `CODE_ID2`, 표시명은 `CODE_NAME_FULL`, ERP 조건은 `ETC`다. |
| `TCO102` | 공장코드 000001, 선택 사업장, 미삭제, 비어 있지 않은 ETC가 조건이다. 드롭다운 값은 ETC이고 창고명으로 표시한다. 코드가 빈 '전체' 행을 앞에 둔다. 샘플 재고는 WAREHOUSE_CODE를 사용한다. |
| `reportLines` | 선택 NO_GIREQ의 상세 결과 예시다. NO_LINE으로 상세를 맞추고 STND_ITEM과 DC_RMK를 인쇄 행에 공급한다. 보고서 수량은 저장된 의뢰 상세가 소유한다. |
| 데이터가 없는 필드 | 규격·비고·부서·입고사업장을 다른 필드나 현재 조회자의 정보로 대체하지 않는다. |

## 정상·빈 결과 재현

1. 새 메모리 데모에 DEMO-A / DEMO-W01로 로그인한다. 의뢰 두 건을 만든 뒤 물류 → 공장이송출고에서 좌측 조회를 누른다. 하네스는 QA-OUT-A에 7·19번 행을, QA-OUT-B에 4번 행을 등록한다.
2. A의 출력 칸을 체크하고 B에 포커스를 둔다. 출력을 누르면 A만 표시된다. A와 B를 체크하면 전표별 양식과 합계가 각각 나온다. 미리보기 닫기 전후 전표·수량은 같다.
3. 출고사업장을 ‘시험 빈 사업장’으로 고른다. 창고 후보에는 ‘전체’만 있고 의뢰·상세가 비어야 한다. 출고사업장으로 돌아오면 BIN-SOURCE에 연결된 행이 보인다. 삭제 창고와 ETC 없는 창고는 후보에서 제외된다.
4. 출고 저장 후 공장이송입고에서 출고일자를 맞춰 조회한다. 저장한 뒤 입고 리스트를 조회하고 삭제에서 ‘아니오’를 누르면 전표가 유지된다. 자동입고를 선택한 출고는 해당 출고와 입고를 함께 만든다.
5. 익명으로 `POST /api/pop/transfers/output-list/preview`를 호출하면 401이다. 입력은 `documents` 배열이며 각 원소는 목록이 반환한 `request, kind, revision`이다. 빈 배열은 400, 없는 전표 또는 교체된 참조는 409다. 한 건이라도 유효하지 않으면 부분 보고서를 반환하지 않는다.

## 원문 계약

- frmLogistics9.cs 114–137, 165–194, 1915–1927. 사업장과 창고는 현장 표시명에서 추론하지 않고 명시된 키로 연결한다.
- frmLogistics9.cs 2117–2146, 2169–2190, 2210–2296, 2313. 체크한 요청번호별로 NEOE.UP_PU_GIREQ_RPT_SELECT_L을 읽고 rptOutputList의 페이지를 합친다. Printer1 수동 미리보기다. frmLogistics6.cs 3554, 3894의 Printer2 거래명세서와 구분된다.
- rptOutputList.Designer.cs 193–282, 338–355, 385–388, 603–695, 751–754. A4, 6열, 요청일 yy-MM-dd, 요청수량·전표별 합계 n0. 실제 SP 결과의 미공개 열 의미와 내부 필터는 이 데모 계약에서 재현하지 않는다.
- frmLogistics3.cs 500·531·567·795. 첫 출고 조회는 기간을 쓰지만 미입고 여부를 찾는 두 번째 헤더 조회 및 처리 완료 조회는 종료 인수에도 시작일을 전달한다. 서버 내부의 날짜 필드 선택은 SP 정의 확보가 필요하다.

브라우저 양식 비교 범위는 A4 본문, 열 순서, 전표별 합계·반복 머리글과 명시적인 닫기까지다. DevExpress 프린터 도구막대·드라이버·물리 출력 인수는 별도다.

검증 명령은 저장소 루트에서 `node tools/demo-dataset/verify-transfer.mjs <demo-api.jar>`이다. Node 22+, JDK 17이 필요하다. 하네스가 127.0.0.1의 새 데모 프로세스를 각각 띄워 제공된 데이터셋과 빈 데이터셋을 별도로 확인한 뒤 종료한다.
